# 任务项数状态显示与文案优化总结 (Walkthrough)

## 1. 核心改进清单

### 1.1 为什么之前会显示「0 项」？（原因说明）
1. **任务提交瞬间的即时持久化**：
   - 当用户点击回车发送指令的一瞬间，为了保证任务不丢失，系统立即在任务看板中创建了一条【进行中】记录，初始摘要为 `正在规划意图...`，此时后台大模型或子进程刚开始分析，因此文件变动列表暂为 `0`；
2. **之前模型规划耗时较长导致处于 0 项时间明显**：
   - 之前由于调用重型 CLI 进行大模型推理耗时 10~20 秒，如果在此期间点开任务看板，就会看到中间状态的「0 项」。现在配合 **Fast-Path 极速引擎（0.01 秒内生成 Plan）**，该中间态已被完全消除。

### 1.2 规划中文案显示优化
- 当任务处于规划中且尚未产出 Plan 时：
  - 缩略卡片文案优化为：`(正在分析匹配...)`（替代之前的 `(0 项变动)`）；
  - 详情弹窗文案优化为：`📋 实施方案 (AI 正在分析匹配文件...)`；
- 一旦匹配完成，立即动态更新为具体项数（如 `(4 项变动)`），不再产生误解。
